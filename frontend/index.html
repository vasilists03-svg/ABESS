1. How the application works

Enter a scalar equation whose free unknown is x. You can manually select a solving method or choose Automatic / rAIson.

In Automatic / rAIson mode, the selected problem criteria are sent to rAIson. rAIson recommends a solving method and Python executes the selected method.

When available, the Results area also displays the explanation returned by rAIson for its recommendation. This helps the user understand why a particular method was selected from the supplied criteria.

If the Automatic / rAIson flow has no usable problem context, the application may use an internal general fallback criterion. This internal fallback is handled automatically and is not a user-selectable criterion.
Selecting a criterion does not manually force a method. The criterion provides information to rAIson, while the final method recommendation remains the responsibility of rAIson.

2. Basic use

  1. Enter an equation.
  2. Select a solving method or choose Automatic / rAIson.
  3. If Automatic / rAIson is selected, choose any criteria that describe the problem.
  4. For numerical methods, initial values are optional. Leave the relevant fields empty to let the application attempt to estimate them. When entering an interval or multiple starting points manually, complete all related fields.
  5. Press Solve.
  6. Press Draw Graph to inspect the function graph.
Both equation and expression forms are accepted. For example, x² - 4 = 0 and x² - 4 are equivalent. If no equals sign is provided, the expression is interpreted as being equal to zero.

8. rAIson Criteria Guide

Criteria describe mathematical properties of the problem or preferences for the solution. More than one criterion may be selected.

Criterion Meaning
I seek an analytical solution Indicates that an exact symbolic solution is preferred when appropriate.
Function is polynomial Indicates that the equation is polynomial in x.
I seek a complex root Indicates that complex-valued roots are relevant.
Derivative is available Indicates that derivative information is available for the problem.
I have a good initial approximation Indicates that a starting value close to the expected root is known.
Integer-valued threshold problem Indicates that the required answer is an integer threshold or integer value.
f(a) * f(b) < 0 Indicates that the supplied interval contains a sign change.
Continuous extension is available Indicates that the function has a suitable continuous extension.
Length of [a,b] >> 1 Indicates that the available search interval is relatively large.
Steep gradient or no gradient near root Describes difficult derivative behavior close to the solution.
Inflection points near solution Indicates that inflection points may occur close to the expected root.
Extremum points near solution Indicates that local extrema may occur close to the solution.
Function behaves smoothly near root Indicates regular and smooth local behavior near the root.
Known k-multiplicity of root Indicates that information about root multiplicity is known.
Function is monotonic Indicates that the function is monotonic in the relevant region.
I need simplicity Expresses a preference for a simpler solving approach.
I need robustness Expresses a preference for robust root-finding behavior.
I need speed Expresses a preference for computational speed.

10. Important input tips

  • Use parentheses when an expression could otherwise be ambiguous.
  • Only one equality sign should be used in a single equation.
  • The solver accepts both standard keyboard notation and several mathematical Unicode symbols.
  • MATLAB scalar operators such as .^, .* and ./ are accepted.
  • Scientific notation such as 1e-8 and 15.8e-6 is supported.
  • For Bisection, fzero and ITP, enter a suitable interval or leave both fields empty to let ABESS attempt to find one automatically.
  • Symbolic Solve may return exact expressions, while numerical methods normally return numerical approximations.

11. Current scope and limitations

The application is designed for scalar equations with one free unknown, x.

Bound variables may appear inside constructs such as definite integrals, finite sums and finite products, but arbitrary additional free variables are not supported.

Polynomial Roots is intended for polynomial equations. Symbolic Solve attempts to obtain an analytical result, but not every mathematical equation has a closed-form symbolic solution.

The input field accepts several MATLAB-style mathematical operators, but it is not a MATLAB programming environment. MATLAB scripts and commands such as for, syms, @(x), optimset or complete MATLAB functions should not be entered into the equation field.

Systems of equations, ordinary differential equations, partial differential equations and general integral equations with an unknown function are outside the current scope.

12. Quick method selection reminder

Manual mode means that the selected method is executed directly. Automatic / rAIson mode means that rAIson determines the method from the supplied criteria, and Python then executes that selected method.

13. Accounts, guest access and password recovery

The application can be used either with a registered account or in Guest mode.

  • Registered users can log in, keep their solve history, access My Information and use a personal API key.
  • Guest users can perform up to 3 free solves.
  • New accounts must verify their email address before they can log in.
  • If a password is forgotten, enter the account email address and select Forgot password?.
  • A password-reset link is sent by email. The link is valid for 30 minutes and can be used only once.
  • Resetting the password does not create a new account. Existing history, account information, role and API key remain associated with the same user.

14. Results and solve history

After a solve attempt, the Results area displays the method that was executed and the result returned by the solver.

In Automatic / rAIson mode, the result can also contain the method recommended by rAIson together with the explanation supplied by rAIson.

A recommendation from rAIson selects the method. The numerical or symbolic computation itself is then performed by the Python backend.

Registered users can open History to review previous solve attempts. The history includes both successful and failed attempts.

  • Success means that the selected method returned a valid result.
  • Failed means that the solve attempt could not produce a valid result.
  • Failed entries include the error code and a readable error message when available.

15. My Information and API access

Logged-in users can open My Information to view their account information and personal API key.

The API key is a private credential. Do not publish it, include it in screenshots, commit it to source-control repositories or share it with other users.

The API allows an external program or script to send equations directly to the same solver backend used by the web application. Numerical parameters such as a, b, x0, x1 and x2 are optional. When required starting values are omitted, ABESS attempts to estimate them automatically.

Solve requests are sent with an HTTP POST request to:

https://abess.hmu.gr/api/equation/solve

The personal key must be supplied in the X-API-Key request header.

Content-Type: application/json X-API-Key: YOUR_API_KEY

Example using a manually selected method:

curl -X POST https://abess.hmu.gr/api/equation/solve \ -H "Content-Type: application/json" \ -H "X-API-Key: YOUR_API_KEY" \ -d '{ "equation": "x^2 - 4 = 0", "method": "bisection", "a": 0, "b": 3, "selected_elements": [] }'

Supported manual method identifiers for API calls are:

bisection newton secant fzero itp muller solve roots integer_exhaustive_scan

Automatic / rAIson selection is requested by setting method to "automatic" and supplying the appropriate problem criteria through selected_elements. The backend also accepts null for compatibility, but "automatic" is the recommended public API form.

For example, the criterion f(a) * f(b) < 0 can be supplied using the ABESS criterion identifier:

{ "equation": "x^2 - 4 = 0", "method": "automatic", "a": 0, "b": 3, "selected_elements": [ "opposite_signs_interval" ] }

The recommended public criterion identifiers for Automatic / rAIson API requests are:

seek_analytical_solution function_is_polynomial seek_complex_root derivative_is_available good_initial_approximation integer_valued_threshold_problem opposite_signs_interval continuous_extension_available length_interval_large steep_gradient_or_no_gradient_near_root inflection_points_near_solution extremum_points_near_solution function_behaves_smoothly_near_root known_k_multiplicity_of_root function_is_monotonic need_simplicity need_robustness need_speed
The application converts these public criterion identifiers to the corresponding rAIson elements internally. API clients therefore do not need to know or depend on rAIson OPT identifiers.
no_context is an internal application criterion. It is added automatically when required and should not be supplied by API clients.

API responses are returned as JSON. Depending on the method and outcome, the response can contain fields such as success, method, root, iterations, error, message, suggestion and rAIson-related information.

Authenticated API solve attempts are associated with the same registered account and are recorded by the application as API requests.

Selecting Regenerate API Key creates a new personal key. The previous API key immediately stops being valid, so any external scripts using the old key must be updated.

16. Understanding errors and suggestions

When a solve attempt cannot be completed, the application tries to provide a clear explanation instead of exposing internal technical details.

An error response may contain:

  • Title — a short description of the problem.
  • Message — an explanation of what prevented the solve from succeeding.
  • Suggestion — a recommended change to the equation, interval, starting values, method or criteria.

Common causes include an unsuitable interval, invalid starting values, a function that is undefined for required values, an equation that does not match the selected method, or failure of a numerical method to converge.

When Automatic / rAIson is used, the rAIson recommendation and its explanation are separate from the solver error message. A valid method recommendation does not guarantee that every numerical input supplied to that method will produce a successful solve.

17. Before reporting a problem

  • Check that the equation contains only the supported free unknown x.
  • Check parentheses, powers and function syntax.
  • For interval methods, review a and b.
  • For Newton-Raphson, Secant and Muller, review any starting values you supplied. If automatic estimation fails, try entering suitable values manually.
  • If using Automatic / rAIson, verify that the selected criteria correctly describe the problem.
  • If an API request fails, verify the endpoint, Content-Type and X-API-Key header.
